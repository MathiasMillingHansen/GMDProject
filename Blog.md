I started by creating a plan which could be used to roll the ball on. Then i had to create the wall to make sure the player couldnt roll of the plane, so i made sure to add collision as well. The next step was then to create the ball. In this case the sphere made most sense. The next step was creating a material which could be used on the "ball". Here i chose a simple grey color.
The next step was then to make the ball able to roll. To do that i needed to add a rigidbody which contains the physics. This made the ball feel like an actual object with gravity and weight / mass. 
Then i needed to make the ball able to actually roll. To do this i created the following attributes: MovementX, MovementY and speed. Then i added the OnMove function, which takes an input value and assigns to the movement attributes which the fixedupdate then uses to add force to the rigidbody which results in the sphere rolling. Then i had to create some pickups that the player can roll into and get some sort of points. Here i added a gameobject and made it a cube. I then added a box collider to the cube and the player so that they can collide and trigger the pickup. I then also added a rigidbody, but made it kinematic and turned off "use gravity" to make the pickups float and not fall to the ground. The next step was making them rotate. To do this i added a new script with one simple line which made he spheres rotate:  transform.Rotate (new Vector3 (15, 30, 45) * Time.deltaTime); I then assigned this script to the pickup and made it a prefab for further use in my game. Now i needed to make sure that the player can actually pickup the pickups. To do this i checked if the player collided with the tag "Pickup", removed  the pickup and incremented the score and updated the score text which i made sure to add so the player can actually see their score. Now i needed some enemies to introduce a challenge to the game. To do this i added a Mesh to the plane which plottet ai movement. Then i basically almost replicated my player object as an enemy but made a new script which uses a navMeshAgent to move the enemy towards the player by using the players position and setting the enemies destination to that. Then i also went into the player and made sure that if the player collided with an enemy, the game would stop and the player would lose. I then added the wincondition of getting all the pickups without colliding with the enemy and added a victory text. I then made a restart button which reloads the scene so that the player can play the game again. The last step was added some small ramps to make som obstacles to make the game more fun. # Blog 3: Working on my own game

In the beginning i wanted to make a binding of isaac clone which featured isaac comming back to deal with all the trauma he has been put through since he was a child. But the complexity of a binding of isaac game was just to much to work for a single person for a school project. So i rethought and wanted to make something simple yet challenging to start with. Therefore i chose a pixel-art based platformer (Kind of like the old Mario games). The first thing i did was making the main menu. To do this i just created a scene with a canvas and added the buttons and wrote a script that took you to the other scenes when you click the button. Then since i know that this should work with a Xbox controller, i plugged my own xbox controller in and woops, it didnt work since i forgot to choose a default selected. After choosing a default selected the controls worked just fine. Then i wanted to create a settings screen where you can adjust the sfx and music volume as well as toggling fullscreen. This was a simple slider i hooked up to an audio controller which has an array of sound effects and music which is played. This was made a singleton since i only need one global instance of the audiohandler. Then i found some simple music and plugged it into the array, now when the scene starts i can choose what song should play in the scene, i then tested turning down the volume which worked just fine. The next thing was creating the first level. I wanted to start with a simple tutorial so i made a simple ramp and platform with some free tilemap assets. Then i added the sprite (also free from the asset store). I added colision to them both and it felt weird. I played around with the colliders and resolved on using a box colider for the upper part of the player sprite and a circle colider for the bottom. This should allow the movement to feel smoother. Also, when playing around with the collision of the environment, there were slights bumps where i had to tune some settings to make the calculation sort of "round" the corners. This happens fx at the start of a diagonal hill up. Then i also had to make the collider sticky otherwise the player would slowly drift down, which felt and looked bad. But then there was another issue, the player could stick to the side of platforms. The solution? Split the tilemap up into ground and platforms, the platforms where not sticky and the ground where and tada the player no longer drifted down and could also not stick to the side of platforms. Next step was adding animations. Here there were some animations that came from the asset store which i used. I used the animator and made the links so that when the player moved, the running animation would play. The only issue i had with the running and jumping animations was with the jumping animation. It tooks some time for me to realize that i could stop the animation from looping, so that once the "falling down" part of the animation was triggered, it wouldnt loop back to the "jumping up" animation. So now i have the start of the tutorial done. 

# Blog 4:

With the animations done for the player it was time to further the game with some level design. First of i wanted to make sure the player couldnt move off the map, there were two ways to do this. I could just add an invisible collider that ensured the player couldnt move past the collider, but i choose to instead make a "mountian" with collision that ensured the player couldnt move of the map. This looked way nicer. What i discovered then were how walls were handled. Since the mountain was a part of the "ground" tilemap layer which had the "Ground" tag, the side of the mountain were "sticky" which meant the player could get stuck in the side of the mountain and keep getting stuck if they held in the respective direction button. This also enabled them to "climb" the wall by getting stuck, technically hitting the "ground" tag which enables them to jump again which they could repeat over and over again. To fix this i added another tilemap called "Edge tilemap" Which will be used whenever there is an edge where the player is supposed to just glide down when they hit it instead of getting stuck. To do this i added another tag called edge which i assigned to the edge tilemap. Now the player could now longer jump when colliding with edges since its no longer a "ground" tag. This also lead to another discovery. Now the "corner blocks" that change the y level which are meant to be jumped up on still have the sticky properties. This meant the player could experience some jank when trying to jump up blocks, again by getting "stuck". To solve this i added another tilemap called "CornerBlocks" which only purpose is to solve this issue. They are completely identical to the ground tilemap except they have 0 friction so the player wouldnt get stuck when trying to jump on top of them. With this now solved i began lengthening the game level. I added more platforms, some obstacles and experimented with world generation making sure to keep the correct tiles in the correct tilemaps. I also created a "middleground" layer so i could add background elements like bushes, houses and trees so the game wouldnt be boring to look at.

# Blog 5:

Now that i have a reasonably lengthy game, i wanted to get to working on the purpose of the game. To find collectibles and get a high score. I already had an idea of how i wanted to do this. I wanted to create enemies which would give points when killed, but they could also kill you. To do this i took the Dino sprite from the SunnyLand Artwork asset from the store and added an animation which was too fast so i lowered the fps so it felt more alligned with the player animation speed. Next up was making sure that the player could kill the enemies to get some score. To do this i needed to make a score system. I knew i wanted to keep the score hiddin during gameplay to make the player feel like they had to move fast since the didnt know how much score they actually had and then display their score at the end, either when they died or when they won the game. This meant i could use a singleton to make a single instance of a score manager which kept track of the score. I also knew that i wanted the score to gradually decrease over time adding a speedrun element to the game for those interested in that. The score manager is very simple, it starts at 20k points and decreases the score by 10 every 500 milliseconds. I also had to make sure the score wasnt ticking down in different menus. So i made it only tick down during the game scene. To ensure the player could damage the enemy i made an anemyhealthcontroller which handles the enemies health and how much damage they take. I made it so that the player has to jump untop of the enemy to deal damage, here i also had to make sure the player didnt take damage from the enemy. Other than that i made it so that the enemy deals damage to the player if it collides with the player. I also added a feature that bounces the player up into the air if they jump on top of the enemy so a skilled player could quickly get rid of the enemies. I also wanted an easy way to controll how far the enemies move. To do this i added a group called enemyboundaryboxes which contains a bunch of colliders that flips the enemies direction if it collides with it. This meant i had great controll of where the enemies would turn around. The next thing was adding collectibles that the player could collect to add 500 points to their score. This was a simple gem again from the SunnyLand Artwork assets with an animation again slowed down. They have a collision that checks if a player tag collides, in which case it adds 500 score and destroys itself.
